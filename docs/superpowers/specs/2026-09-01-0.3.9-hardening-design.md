# ScarletX 0.3.9 Hardening Design

## Goal

Ship ScarletX 0.3.9 as a maintenance release that closes the security, correctness, performance, and supply-chain gaps identified in the 0.3.8 audit without adding user-facing feature scope.

## Global constraints

- Version series remains `0.3.x`; this release is exactly `0.3.9`.
- Nginx remains the only public HTTP service; FastAPI stays internal on port 8000.
- Existing 0.3.8 databases and storage layouts must upgrade in place.
- TrueNAS SCALE remains a primary deployment target.
- Existing adult-scene behavior, metadata, downloads, imports, and automation must remain compatible.

## Security design

### First-run administrator setup

Initial administrator creation must require a one-time setup token. ScarletX generates a cryptographically random token when no administrator exists, stores only its SHA-256 digest in `/config/setup-token.json` (or `SCARLETX_SETUP_TOKEN_FILE`), writes the plaintext token to startup logs, and accepts an explicit `SCARLETX_SETUP_TOKEN` override for automated deployments. The browser setup form asks for this token. After the first administrator is created, the token file is removed and the token is no longer accepted.

### Runtime identity

Both backend and web containers run as non-root UID/GID 568 by default. Writable image-owned paths are prepared for that identity. Bind-mount users must ensure `/config`, `/downloads`, `/media`, and `/backups` are writable by the selected runtime identity.

### Archive extraction containment

ZIP path checks remain. RAR/7z extraction gains preflight member-path validation, extraction into a private quarantine directory, rejection of absolute/parent-traversal paths and symlink escapes, then validated promotion into the completed directory. Archive passwords are cleared from job records after terminal post-processing.

### HTTP/browser hardening

Nginx applies security headers to static frontend and proxied responses: nosniff, no-referrer, DENY/frame-ancestors none, restrictive permissions policy, object/base restrictions, and a CSP compatible with the current inline legacy frontend. Nginx hides version tokens, enables gzip, and caps request bodies at 100 MiB. API keys are accepted only through `Authorization: Bearer` or `X-Api-Key`, never query strings.

Nginx passes a controlled forwarded scheme to the backend using `SCARLETX_FORWARDED_PROTO` (`http` by default, `https` when ScarletX is behind trusted TLS termination). `X-Real-IP` remains overwritten by Nginx for login-rate limiting.

### Secrets at rest

Secret `AppSetting` values are encrypted with Fernet using an installation key stored in `/config/.scarletx-secret.key` (or `SCARLETX_SECRET_KEY_FILE`) with mode 0600. Existing plaintext secret rows are transparently migrated. Non-secret settings remain plaintext. The install key itself is never stored in the database.

## Performance design

### Authentication

Session lookup becomes a single joined `AuthSession`/`AuthUser` query. Protected-route middleware no longer performs an unconditional `admin exists` query before every request.

### SQLite

Keep WAL/NORMAL/busy timeout, but reduce the connection pool to 5 + 5 overflow and lower the per-connection cache to 16 MiB. This limits memory amplification while retaining concurrent readers.

### Library scans

Build an in-memory normalized-title index once per scan. Exact titles use a dictionary; substring candidates use a longest-token anchor index, avoiding a full `files × scenes` comparison. Media probes are bulk-loaded into a dictionary rather than queried one-by-one.

### Completed-download polling

Batch-load tracked metadata and native job state for all pending downloads. Apply non-terminal status changes in grouped transactions while leaving filesystem import and metadata operations isolated per completed item.

### Frontend/activity

Keep SSE as the primary activity transport and existing shared queue cache. Add gzip for static/API text payloads; retain polling only as fallback.

## Supply-chain design

CI installs and runs `pip-audit` against the installed project dependencies. Add Dependabot configuration for pip, Docker, and GitHub Actions. Container/test workflows continue building both images. Release validation must remain a hard gate before publishing 0.3.9.

## Testing

Add focused tests for setup-token enforcement/lifecycle, query-string API key rejection, session query behavior, encrypted secret migration/round-trip, archive path validation/quarantine, non-root Docker contracts, Nginx headers/body cap/gzip/forwarded scheme, SQLite pool/cache limits, indexed library matching, batched download-state loading, password clearing, dependency-audit workflow contracts, and 0.3.9 version metadata. Existing Python 3.11/3.12/3.13, Docker image builds, and TrueNAS render/deploy validation must remain green.
