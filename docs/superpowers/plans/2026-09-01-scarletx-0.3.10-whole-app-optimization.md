# ScarletX 0.3.10 Whole-App Optimization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver ten measured optimization PRs that reduce ScarletX latency, database and filesystem work, duplicate processing, frontend polling, download overhead, module size, and deployment cost without breaking upgrades or supported deployments.

**Architecture:** Work proceeds serially from `release/0.3.10`: every task creates a fresh feature branch, proves one optimization with tests and measurements, opens a PR back to `release/0.3.10`, merges only after all gates pass, and deletes the branch. The first task creates the measurement contract; later tasks reuse it and must retain only changes that improve their declared metric without correctness regressions.

**Tech Stack:** Python 3.11-3.13, FastAPI, SQLAlchemy 2, SQLite, httpx, asyncio, watchdog, pytest, vanilla HTML/CSS/JavaScript, Nginx, Docker Compose, TrueNAS `ix_lib` templates, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-01-scarletx-0.3.10-performance-design.md`

## Global Constraints

- `main` remains stable at 0.3.9 until beta.1, beta.2, and beta.3 are accepted.
- Every implementation branch starts from the latest `release/0.3.10` and every PR targets `release/0.3.10`.
- Existing SQLite databases, encrypted credentials, queues, paths, and container storage upgrade in place.
- FastAPI remains private on port 8000; Nginx remains the only public HTTP entrypoint.
- Python support remains `>=3.11`; no production frontend build runtime is introduced.
- State transitions, cancellation, completion, failure, and shutdown checkpoints remain immediately durable.
- Secrets, credentials, authorization headers, and raw secret-bearing command output never enter logs, events, or benchmark artifacts.
- A performance change is merged only when focused tests, the full suite, and its declared before/after measurement pass.
- Each PR description records baseline, result, environment, commands, compatibility impact, and rollback behavior.

@dataclass(frozen=True)
class BenchmarkResult:

    iterations: int

- [ ] Run Python 3.11, 3.12, and 3.13 test matrices, Ruff, dependency audit, and source compilation.
- [ ] Build backend and web images and verify anonymous pulls.
- [ ] Render and install the TrueNAS package with `basic-values.yaml` and verify the live health endpoint.
- [ ] Repeat list, scan, queue, TPDB, active-download, image, startup, and memory benchmarks on the same host used for baseline.
- [ ] Verify a populated 0.3.9 database upgrades without data or secret loss and rollback instructions restore the backup.
- [ ] Create `release/0.3.10-beta.1` metadata only after every gate passes; do not move `main`, `latest`, or final `0.3.10` tags.
